# 按模板交付数值模型结果

## 触发

用户给出**已冻结的数学模型/数值方法规范** + 数据附件 + 结果模板，要求实际计算并交付结果文件（Excel/CSV 等）。典型：数学建模题、PDE/仿真交付。

核心纪律：**不重新设计模型**。你的任务是实现、运行、修正、验证。

## 步骤

1. **定权威规范。** 通读全部指导文档，选最具体/标注为“最终框架/强制规则”的那份为唯一依据。若文档互相矛盾（如初值接力 vs 各自从初值起算），按最具体者执行，并**把冲突与取舍写进项目经验文件**，不自行发明第三种方案。完成判据：能用一句话说出“依据哪份文档、为何”。

2. **脚本化核实输入，不信文档里的数字。** 用脚本（openpyxl/pandas）读取附件与模板，打印真实 sheet 名、行列数、首末行、时间跨度、单调性。文档中的“共 N 条记录”经常与文件不符。完成判据：记录数、量纲、单位转换（cm↔m、K↔°C）全部有实际证据。

3. **先小后大。** 正式计算前，用**粗网格（如 N=64）+ 短时间窗**跑一次冒烟测试，检查：初始条件、边界符号、量纲、输出维度。确认物理趋势合理（如表面先变化、中心滞后）再上生产网格。完成判据：冒烟结果与手算/量级估算一致。

4. **做三类独立验证，缺一不可。**
   - 网格收敛：比较 N 与 2N（必要时 4N）的同一输出量，要求变化远小于报告精度；事件型题目单独比较**终点时间**。
   - 解析基准：构造常系数、简单边界（如 Dirichlet）的合成问题，与解析级数（柱/球用 scipy.special.jn_zeros 等）比较。
   - 退化极限：让新模型退化到已知模型（如移动边界令 R(t)≡R₀），两者应在机器精度内一致。
   完成判据：三类验证都给出可复现的数值证据。

5. **事件判终点用未舍入值。** 监测 g(t)=max(状态)−阈值，传 `events=` 给求解器并取第一次穿越；必要时用 brentq 在稠密输出上复核根。舍入只在写文件时做。完成判据：终点处 g≈0 且穿越方向正确。

6. **写入模板副本，不覆盖原件。** 复制模板再写；保留原工作表名与表头语义；数值写成 float 并设 number_format（如 `0.0000`），不要把数值转成字符串。移动边界情形：域外位置留空（None），并单列输出动边界表面值。完成判据：单元格类型为数值、显示精度符合要求。

7. **回读校验每个产出文件。** 重新打开成品文件逐项检查：工作表名、行/列数、逐格有限性、末行/末列关键值。**对可能为空的单元用 nan 感知比较**（`np.nanmax` / 先筛 `np.isfinite`），否则域外空单元会让 `np.max` 返回 NaN 并误报。回读用 `load_workbook(read_only=True)` + `iter_rows` 批量取数，避免逐格 `ws.cell` 导致分钟级耗时。完成判据：结构、精度、终止条件（在全域内部而非单点）全部通过。

8. **留痕。** 保存配置、输入 SHA-256、依赖版本、网格与容差、未舍入事件时刻、验证状态到 run summary；把验证结论写入验证报告。完成判据：任一数字都能追溯到具体配置与运行。

9. **对方要独立反验证时，交一个可复现包。** 打包 `src/`、`configs/`、`inputs/`（原始附件 + 模板，且**配置里的路径指向 `inputs/…`**，保证解压到任意目录即可运行）、`outputs/diagnostics/`（收敛/敏感性/事件轨迹/run summary）、`requirements.txt` 与 `pip freeze` 生成的 lock、README 与实现细节问答文档。完成判据：把包解压到干净目录，在那里重跑一次求解，得到的数字与主项目**逐位一致**。

10. **随包发布未舍入原值与事件邻域轨迹。** 导出 `event_raw.json`（raw 秒数、事件处 max 状态、阈值与方向定义），并输出终点前后 ±120 s、每 1 s 一行的轨迹（**整秒网格 + 精确事件行**；列含 max 状态、argmax 索引与坐标、中心值、表面值、`event_value = max状态 − 阈值`）。小时数**一律由未舍入秒数换算后再舍入**，绝不用已舍入秒数反算（例：70759.978 s→19.6555 h，而 70760.0 s→19.6556 h）。

## 注意

- 配置默认用 JSON；**只有当对方明确要求 YAML 时才装 pyyaml**，不为一个格式依赖擅自改系统 Python。
- 校验脚本要容忍按需裁剪的交付包：读取器遇到缺失文件应**跳过并提示**（strict 可选），而不是直接断言失败。
- 报告“完成”前，结果文件必须已被回读验证；仅在控制台打印不算验证。
- 报告“完成”前，结果文件必须已被回读验证；仅在控制台打印不算验证。
- 结果与题面背景表述不符时，先判“程序/数值错误”还是“模型参数口径”。若已有网格/容差稳定性 + 解析/极限一致性支撑，则属后者，**停下报告给用户决定**，不要擅自改模型参数。用户确认后的标准处理：**保留“严格按题设模型”的主结果不动**，补做关键参数敏感性（如表面传质系数、扩散系数量级、边界平衡量各 ×0.5/1/2），再把差异来源写进交付文档（README/验证报告），指出背景时长是**工艺背景**、模型未包含的物理（如蒸发潜热、吸附平衡）导致理论值偏短。
- 用户可能给出与自算收敛值略有差异的数字（如终点时间差 0.003%）。**报出自算收敛值 + 不确定度（网格/容差离散度）并说明口径差异**，请用户确认采用哪个，不要凑数。

## 交付前自审（反向验证最常抓的几处）

- **网格术语写准。** 节点中心有限体积中 N 是**径向区间数**，节点与控制体都是 N+1（首末为半控制体）。配置项命名（如 `radial_intervals`）与 run summary 字段照此写；含糊的“N 个控制体”会被判为与实现不一致。
- **事件复核要真跑。** brentq 的括号必须真正异号：事件端点常是 ~1e-17 的正数，用 [t−window, t] 会**静默不执行**，此时 `t_refined == t_event` 不是证据。做法：事件后多积分一小段（如 150 s），在 g>0 与 g<0 的区间上求根，并把 `brent_executed` 写进运行记录。
- **阈值表述用严格式。** 临界时刻满足 `max = 阈值`，**其后**才严格小于；不要写“max < 阈值 (OK)”。可另给整数秒安全时间（ceil(t\*)），但不得用它替代理论临界时间。
- **不确定度合并来源。** 报“时间积分误差 + 空间离散误差”的综合量（如 <0.04 s），不要只给积分容差；若有网格三档，附收敛阶与 Richardson 外推。
- **收支检查覆盖每个问题。** 多问共用一套离散时逐个写入守恒残差表；移动/收缩域必须用**材料参考域**度量 `M_ξ=ΣV_i^ξ c_i`，绝不用当前物理体积积分，否则几何收缩会被误当成水分流失。
- **依赖文件分开且可移植（修正第 9 步的 lock 做法）。** runtime 与 dev 依赖分文件；lock 用可移植的 PyPI 版本钉，不要直接贴发行版 `pip freeze`（会混入 `+dfsg`、`0.0.0` 之类的系统包快照）。
- **交付代码风格。** 注释简短；不用成排的 `# ----` 装饰分隔；命令输出需要分隔时用 `"=" * n`。
- **元数据改了就要重生成产物。** 改动任何产出元数据的代码（网格字段名、阈值/校验措辞、事件字段）后，必须重跑生成器让 `event_raw.json`、run summary、验证报告等**全部**产物同步更新，别只手改一个文件；同一字段名（如 `radial_intervals`/`nodes`/`node_centred_control_volumes`）在所有产物中保持一致。回读校验的输出也要用严格式措辞（临界行 `max ≈ 阈值`、其前一行 `> 阈值` 证明穿越），安全整数秒在**轨迹上抽样**验证而非依赖 Excel 行。依赖上：dev 的版本范围不得与 lock 钉的版本冲突（如 `>=3.8` vs `==3.6.3`），未使用的重依赖不要列入，顶层版本快照不得宣称是完整锁文件。
- **拆分/重构已验证求解器后，用输出精度证明等价。** 把“一题一文件”之类的重构版与原版对照时，逐格比较**舍入到交付精度**的值（如 `"%.4f"` 全部相同）即可判定等价，不要比较原始浮点：积分步序列不同会带来 ~1e-6 的差异，看着像不通过却对交付毫无影响。重构版若要求单独运行，路径一律从 `__file__` 解析，保证任意工作目录可跑。
